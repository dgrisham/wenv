# Wenv → Nushell Port: Status & Context

## Overview
The `wenv` working environment manager has been ported from zsh to Nushell.
The core command, all extensions, and all 34 wenvs are migrated. The zsh
version remains intact alongside — both can coexist.

## What Was Ported

### Core (`nu/wenv.nu`, ~330 lines)
Nushell implementation of `wenv` with subcommands. Sourced from the repo
directly in `config.nu`:
```nu
source ~/src/wenv/nu/wenv.nu
```

Subcommands (tab-complete via `@` annotation on args):
- `wenv start <wenv> [--no-init] [--detach]` — creates/attaches tmux session, sources wenv
- `wenv stop [--force] [--no-shutdown]` — runs shutdown, clears `_source.nu`
- `wenv source <wenv> [--cd]` — generates source script, prints source command
- `wenv cd [wenv]` — cd into a wenv's WENV_DIR
- `wenv edit [wenv]` — opens wenv file in $EDITOR
- `wenv new <name> [--dir] [--init]` — creates from template
- `wenv ls` — lists all wenvs
- `wenv rm <wenv>` — deletes a wenv
- `wenv mv <old> <new>` — renames a wenv
- `wenv bootstrap <wenv>` — runs bootstrap in subprocess
- `wenv extension load/edit/remove` — manage extensions

Short names only (`ls`/`rm`/`mv`) — no long-name duplicates in completion.

        └── ... (34 total)

$WENV_EXT ($SRC/wenv/nu/extensions/)  # in the git repo
├── wd.nu

### Nushell Config (`~/.config/nushell/`)
- `env.nu` (103 lines) — PATH, directory vars, editor, app configs, prompt
- `config.nu` (258 lines) — vi mode, aliases, keybindings, wenv.nu source line
- `theme.nu` (70 lines) — color scheme (sourced via `$env.config.color_config`)

### Wenv File Format
```nu
$env.WENV_DIR = "/path/to/project"
$env.wenv_deps = [parent/wenv]
$env.wenv_extensions = [wd, edit]

def startup_wenv [] { }
def shutdown_wenv [] { }
def bootstrap_wenv [] { }

if ($env | get -o only_load_wenv_vars | default false) { return }
# --- runtime setup below ---
$env.wenv_dirs = { src: "src", test: "test" }
```

The `only_load_wenv_vars` guard is preserved — `wenv cd`, `wenv bootstrap`,
etc. run the wenv in a subprocess with this flag to extract config vars without
executing the body.

### Extensions (in `nu/extensions/`)
- **wd.nu** — `wenv_dirs` record for named directories. `wd <key>` outputs path, `c <key>` cd's into it. Tab-completes keys via `@wenv-complete-dirs`.
- **c.nu** — (stub, functionality merged into wd.nu)
- **edit.nu** — `wenv_files` record for named files. `wenv-edit <key>` opens in $EDITOR.
- **notes.nu** — sets up `$NOTES_DIR`, adds `notes` key to `wenv_files`
- **git-worktree.nu** — `add-worktree`/`remove-worktree` with `wenv_dirs` integration

### Key Design Decisions Made
1. **`source` over `overlay`** — overlays were considered but `source` + generated
   `_source.nu` was simpler and matched the zsh mental model.
2. **`_source.nu` is persistent** — lives at `~/.config/wenv/_source.nu` (not `/tmp`).
   Every new shell sources it. `wenv stop` writes a no-op comment to it.
3. **Completions via `@` annotations** — nushell's `@completer_fn` on def params,
   not `extern` declarations.
4. **Prefix completion mode** — fuzzy completion is broken with single-character
   commands like `c` (matches all builtins containing "c"). Set to prefix matching
   as a workaround. No nushell fix available.
5. **Extensions in the git repo** — referenced via `$env.WENV_EXT` (`$SRC/wenv/nu/extensions`),
   not `$WENV_CFG/extensions/`.
6. **Wenvs in `nu-wenvs/`** — separate from the zsh originals in `wenvs/`.
7. **Tmux default shell** — set to `/opt/homebrew/bin/nu`.

### Shell Configuration
- Vi mode with beam (insert) / block (normal) cursor — both modes show `> ` prompt
- History ghost text (dark gray `#666666`) with Ctrl+F (word) / Ctrl+Space (full)
- Table mode: `light` (no borders, header separator only)
- Auto-ls on cd
- All zsh aliases ported (git, brew, fd, etc.)

### Known Issues
- **Fuzzy completion + `c`** — single-char command names pollute completion with
  all builtins containing that letter. Workaround: prefix matching mode. No
  upstream fix.
- **`source` is parse-time** — can't conditionally source files with `if`. The
  `_source.nu` file must always exist (even if empty/comment-only).
- **`$env.` prefix required** — nushell requires `$env.VAR` not `$VAR` for
  environment variables. More verbose than zsh.
- **`wenv_dirs` values can't use `"$env.HOME"`** — must use bare `$env.HOME`
  (evaluated at runtime) or string interpolation `$"($env.HOME)/subdir"`.

## Nushell ↔ Zsh Reference
| zsh | nushell |
|-----|---------|
| `source file` | `source file.nu` (parse-time, path must be literal or `~`) |
| `export VAR=val` | `$env.VAR = val` |
| Assoc arrays (`wenv_dirs`) | Records: `{tmp: "/tmp", src: "~/src"}` |
| `compdef` / `_arguments` | `@completer_fn` annotation on `def` params |
| `unset VAR` | `hide-env VAR` |
| `noglob` | Not needed — nushell doesn't glob-expand by default |
| `getopts` / arg parsing | Built into `def` with typed flags |
